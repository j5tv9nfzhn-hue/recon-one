# 授权与使用边界

本文是**使用前提**，不是免责声明。它的作用是把「什么时候可以用这个工具」写成可核查的条件，
而不是留给使用者自行解释。

## 1. 允许的用途

只在同时满足下面三条时使用：

1. **你拥有目标，或持有目标所有者签发的书面授权**，且授权覆盖本次侦察的**范围**与**时间窗口**；
2. 你已了解所在司法辖区关于未授权访问的规定，并确认本次操作不落入其禁止范围；
3. 一旦授权变更、到期或被撤回，你会**立即停止**并按要求处置已产生的数据。

常见可接受场景：自有资产自查、签约渗透测试的前期侦察、SRC/漏洞赏金项目**规则允许**的资产
（注意：多数 SRC 只允许特定域名与特定手法，规则优先于本文）、教学环境中的靶场。

## 2. 明确禁止

- 对未获授权的第三方目标运行本工具，**包括**「只是想看看」、以公开信息为由、或认为目标「反正没锁」。
- 用本工具的输出（端点清单、密钥线索、历史路径、子域）对未授权目标发起进一步测试。
- 将报告、`raw/` 目录或其中的密钥线索转交给未获授权的第三方。
- 把本工具当作漏洞扫描器或渗透执行工具使用：它不发送攻击载荷，但**输出的地图足以支撑攻击**，
  因此数据处置与扫描行为同等受约束。

## 3. 记录方式（可核查）

授权不是口头承诺，而是**写进每一份报告**：

| 位置 | 内容 |
|---|---|
| `report.json` → `meta.authorization` | `notice`（完整声明）、`summary`、`notice_version`、`premises`（三条前提）、`authorized_by`、`declared` |
| `report/report.md` | 「授权声明」一节，含授权依据与使用前提 |
| `report/handoff.md` | 第 0 节一行：短声明 + 授权依据 |
| `report/brief.md` | 第 0 节一行：同上（下游 agent 第一眼可见） |
| 控制台 | 登录页与扫描页常驻短声明；扫描页有「授权依据」输入框 |
| 运行时 | `scan` 在首个请求前打印完整声明；`ui` 在打印配对令牌前打印声明 |

`--authorized-by`（控制台对应输入框）是可选的自由文本，建议填工单号、合同编号或授权窗口。
**留空不会被拒绝，但报告会明确写「未声明」**——这比假装有授权更诚实，也让事后审计能分辨
「没有记录」和「记录了但没有」。

```powershell
python -m reconone scan --domain example.com --authorized-by "SOW-2026-014 / 2026-11-01..11-30"
```

## 4. 数据处置

- `runs/<target>/raw/` 内含**密钥原文**（报告正文只有掩码 + 哈希）。这是刻意的：复核需要原文。
  因此该目录按**同等级别**保管，不要放进共享盘、公开仓库或工单附件。
- `state/auth.json`（PBKDF2 凭据）与 `state/sessions.json`（会话哈希）已在 `.gitignore` 中排除，
  `runs/` 同样排除。仓库里只有代码。
- 项目结束后按授权约定删除或归档 `runs/<target>/`；`.gitignore` 只防误提交，不构成数据销毁。

## 5. 免责

本工具按「现状」提供，不对输出完整性、准确性作任何担保，也不对使用者的行为承担责任。
**是否获得授权、是否合法使用，由使用者自行判断并承担全部后果。**
报告中的价值/难度/机会指数是**可解释的机会排序，不是漏洞概率**，不得作为「可以攻击」的依据。

## 6. 报告与文档的关系

本文的条文与 `reconone/config.py` 中的 `AUTHORIZED_USE` / `AUTHORIZED_USE_PREMISES` 是**同一份内容**：
代码是唯一来源，报告从代码取，文档同步于代码。改条文时三处必须一起改，否则报告会声称一份
文档里不存在的承诺。

仓库级声明与「本工具自身漏洞」的报告渠道见根目录 [SECURITY.md](../SECURITY.md)；
它同时写明五层脱敏的作用范围与 `raw/` 这一处有意保留的例外。
GitHub 仓库描述（About）也带同一句授权要求，因此访问者不必先读文件就能看到边界。
