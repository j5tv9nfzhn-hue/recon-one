# 导入到 ARTEX 的模板正文

> 用途：在 ARTEX「新建任务 → 任务模板」里粘进 `description` 字段（上限 16,000 字符）。
> 生成方式：`python -m reconone brief --report runs/<domain> --out runs/<domain>/report/brief.md`
> 然后把 `brief.md` 全文粘到 `{{BRIEF}}` 的位置。

---

## 模板：recon-one 预置情报

**name**（≤120 字符）

```
recon-one 预置情报 · <domain>
```

**description**（≤16,000 字符）

```
{{BRIEF}}

---

## 侦察者给后继 Agent 的说明

上述内容全部来自自动化侦察，**已带证据、可直接采信**：

- 端点表格里 `置信度=high` 的行直接来自 JS 调用点或 OpenAPI 规范，不需要再验证存在性；
- 内部命名空间（`.corp/.internal`、私网段）已达则需内网立足点，不要浪费轮次从外网爆破；
- 前端密钥只给掩码与哈希，原文在 `raw/js/` 内，需要时按路径读取；
- 若「未覆盖」一节为空，说明该层已探尽，把预算投到 §7 的动作上。

**不要重复做的事**：下载 JS bundle、手工找 source map、正则扒端点、猜 API 路径。
这些都已经做完了，重复只会消耗 token 而不产生新信息。
```

**goal**（≤16,000 字符）

```
基于简报中已确认的公开面，按 §7 的优先级推进：
1) 先验证无阻塞项（匿名可测的路径、已泄露的 source map、硬编码凭据）；
2) 再处理需要额外条件的项（对象级授权、GraphQL 权限边界），
   若缺少测试账号则记录为阻塞并转向下一项；
3) 每条结论必须带可复现证据（请求/响应或命令输出），
   不要仅凭状态码推断漏洞。
```

---

## 为什么这样写

| 设计 | 原因 |
|---|---|
| 第一行是裸 URL | ARTEX 的 `seed()` 会对 description 跑 `parseTarget()` 正则可提目标主机；若首行是「目标见附件 xxx.txt」，会把文件名当域名 |
| 明写「不要重复」 | 模型没有上下文时默认行为就是「先扫一遍」，必须显式禁止 |
| 区分「未覆盖」与「已探尽」 | recon-one 的 `coverage.probes` 区分 `skipped`/`none-found`/`ok`，这个信息对规划很有用 |
| 优先无阻塞项 | 对应 `handoff.md` 的停机条件：缺账号时不要空转 |
